# 冻结画面最暗／最亮自动标注：简要设计

## 目的与范围

用户要求点击测定点固定画面后，自动看到画面的最暗和最亮位置。此功能用于查看，不代替用户选择曝光主体。

固定画面时在取景图像上显示“最暗”和“最亮”两个小标记；标记跟被冻结的测量帧一起保留，退出冻结、换镜头或使当前画面失效时清除。连续测量与“单次”保持读数的现有行为不变。

## 方案取舍

选择的方案：只用进入冻结状态的 `Frame` 计算自动极值，与手动 `Spot` 分开保存和绘制。这样标记位置不会叠到后来变化的实时画面上，实现范围集中且保留现有操作。

未选择底部“单次”联动冻结：它会把保持读数和冻结取景合并，违背已有交互。未选择连续追踪极值：没必要这不仅是一项用户未要求的功能，实时移动也容易使标记抖动。

## 计算与显示

- `Frame` 的有效候选中心是 alpha 不为零的已有图像像素；缺失视场不能产生坐标或 EV，邻域的透明黑白像素也不计入亮度。
- 固定当前帧及响应表后先恢复界面交互，计算在既有测量线程完成。只有帧对象和冻结请求编号仍然匹配才发布；退出冻结、相机失效、换镜头或新校准都会取消旧请求的可见结果。
- 候选点沿用现有点测光的 5×5 有效像素线性亮度平均，使用当前镜头响应得到 EV100。比较候选点的真实 EV，找绝对最小和最大值，不使用像素百分比评分或分位数替代结果。
- 以像素中心 `(x + .5) / w, (y + .5) / h` 计算归一化坐标，和现有取景 Canvas 一致；为避免恰好落在整数边界时被截断到前一像素，内部取样仅偏移百万分之一像素，不影响可见定位。相同亮度按行优先、从左到右选择，累加误差小于 0.000000001 EV 时仍视为并列，保证结果可重复。
- 自动数据类型为 `ExtremalSpot`，两点集合为 `FrameExtremes`；它们没有手动编号，也不能成为 `safetyPointId`。
- 最暗点用蓝环，最亮点用琥珀环，深色外描边和文字保证不同亮度背景上的可读性。无障碍说明明确两点仅为当前画面的估计。
- 局部触及已编码的 0／255 时沿用现有的 `cameraLimitedAt` 提示，不改变相机触限警告或胶片安全范围。

## 保持不变的边界

曝光求解、平均／点测光计算、校准、胶片与 LUT、拼接、单次／连续／冻结各自的状态以及退出 HOLD 才应用曝光的规则均不改变。自动标记不会自动选主体、生成推荐、推动曝光补偿或引入全屏警告。

## 验证与发布

用 JVM 测试验证亮度、边界、缺失视场、坐标、并列结果及不同画面尺寸；用仪器测试验证固定画面出现标记、手动测光点仍可添加、自动点不参与安全主体、退出后清除且单次／冻结不混合。完成既有全部回归和 Android 15 模拟器截图。

从 `b1b7ea2` 创建 `ui/frozen-extrema` 分支。当前目录已经是该功能的干净独立分支工作区，不另建工作树。后续试用版沿用独立包名、签名并递增 `versionCode`；只有用户试用确认后才考虑合并正式 `main`。
